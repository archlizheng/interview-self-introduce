# interview-self-introduce｜面试自我介绍 Skill

`interview-self-introduce` 是一个用于 **生成面试自我介绍** 的 Codex Skill。它可以把「请做个自我介绍」这种开放问题，变成一段更贴合岗位、更自然、更可信的 30 秒 / 60 秒 / 90 秒 / 120 秒面试开场白。

它适合用在求职面试准备中，尤其是你有目标岗位 JD、简历、项目经历、实习经历，或者只有一些零散背景信息时，帮助你整理出一段能直接开口说的自我介绍。

## 它能解决什么问题？

很多自我介绍容易出现这些问题：

- 像流水账一样复述简历：从学校、公司、时间线一路念下来；
- 只堆关键词：比如「沟通能力强、学习能力强、抗压能力强」；
- 太模板化，听起来像 AI 写的；
- 为了显得厉害而夸大经历，面试官追问时容易露馅；
- 不知道不同轮次该突出什么：HR 面、业务面、技术面、终面、英文面都说成一个版本；
- 不知道 30 秒、60 秒、90 秒分别该说多少。

这个 Skill 的目标不是把你包装得很夸张，而是帮你从真实经历里提炼出 **岗位相关、说得出口、经得起追问** 的表达。

## 主要功能

- 根据 JD 和简历生成岗位定制版自我介绍；
- 支持 HR 面、业务/用人经理面、技术面、终面、英文面；
- 支持 30 秒、60 秒、90 秒、120 秒不同长度；
- 支持中文、英文、中英双语输出；
- 能把普通经历提炼成更像面试表达的证据点；
- 能改写流水账式、模板化、过度口号化的自我介绍；
- 会提醒哪些说法有风险、哪些内容不建议说；
- 可补充面试官可能追问的问题和练习建议。

## 适合谁用？

- 应届生、实习生：经历不多，但需要把课程、实习、项目、社团活动说清楚；
- 转行求职者：需要解释过往经历和目标岗位之间的关联；
- 初级候选人：没有特别亮眼成果，但想把实际做过的事情说扎实；
- 有多年经验的候选人：需要把复杂经历压缩成 1-2 分钟的清晰开场；
- 准备英文面试或双语面试的人；
- 已经写了自我介绍，但觉得太模板、太长、太虚的人。

## 使用方式

把本文件夹放到 Codex 的 skills 目录下，例如：

```bash
~/.codex/skills/interview-self-introduce
```

然后在 Codex 里这样调用：

```text
使用 $interview-self-introduce，帮我根据这份 JD 和简历写一个 90 秒中文业务面自我介绍。
```

也可以用更轻量的方式：

```text
使用 $interview-self-introduce，岗位是财务助理，我是审计专业本科，有半年审计实习，帮我写一版 60 秒自我介绍。
```

## 推荐输入信息

如果你希望生成更完整、更贴合岗位的版本，建议提供：

1. **目标岗位或 JD**：岗位名称、职责、任职要求；
2. **简历或经历材料**：教育背景、工作/实习经历、项目经历、成果；
3. **面试轮次**：HR、业务/用人经理、技术、终面、英文面；
4. **目标时长**：30s、60s、90s、120s；
5. **输出语言**：中文、英文或中英双语。

完整字段可以理解为：

```text
interviewRound: hr | hiring-manager | technical | final | english
duration: 30s | 60s | 90s | 120s
language: zh-CN | en | bilingual
```

如果缺少信息，Skill 会先追问关键问题；如果只是轻量场景，也可以先基于已有信息生成一个临时版本，并明确标注假设。

## 典型输出内容

一次完整输出通常会包含：

- 输入信息摘要；
- 对岗位要求的理解；
- 简历/经历与岗位要求的匹配表；
- 推荐版口语化自我介绍；
- 可选的短版或替代版本；
- 面试官可能追问的问题；
- 有风险、不建议说或暂时省略的内容；
- 质量检查：是否贴合岗位、是否真实、是否符合时长、是否自然。

## 设计原则

1. **先讲证据，再做润色**  
   重要表达应来自简历、项目、JD 或用户明确提供的信息。

2. **要像人说话，而不是像模板**  
   输出应适合面试现场直接开口说，而不是一段正式履历简介。

3. **突出岗位匹配，而不是复述时间线**  
   将经历压缩成 2-3 个和岗位相关的证明点。

4. **控制夸大风险**  
   避免没有依据的「精通」「主导」「全面负责」「显著提升」等说法。

5. **根据面试场景调整重点**  
   HR 面更关注动机和稳定性，业务面更关注岗位匹配，技术面更关注项目细节，终面更关注发展逻辑。

## 简历处理说明

这个 Skill 本身是文档型 Skill，不内置简历解析脚本。

推荐做法：

- Markdown 或粘贴文本：可以直接作为简历证据使用；
- PDF / DOCX / DOC：建议先用简历转 Markdown 工具处理；
- 扫描件或图片简历：需要用户提供文本，或明确同意 OCR；
- 如果简历无法解析，不应编造经历。

详细规则见 [`references/resume-input.md`](references/resume-input.md)。
