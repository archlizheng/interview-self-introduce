# Anti-Patterns

## Chrono Resume Read-Through

**Bad**: "2025 I was at DJI... before that Kunlun... before that Mango TV for four years..."

**Why it fails**: Interviewers already have the resume. They want role-fit proof, not a timeline.

**Fix**: Pick 2–3 capability themes tied to the JD. Mention companies only inside evidence, not as the spine.

## Skill Keyword Stacks

**Bad**: "I know Python, LangChain, RAG, MCP, Agent, Dify, coze..."

**Fix**: One verb + one project per capability: "In project X I used RAG to ... and measured ..."

## JD Fit Without JD

When `jdText` is missing:

- Do **not** use "最能和这个岗位对应", "perfect fit for this role", etc.
- Use a general positioning + 2 representative projects.
- In the evidence map, label the first column `（无目标 JD）...` or use `能力主题` and note in `岗位理解` that no JD was provided.
- End with a hook asking for the target role requirements.

## Duration Too Short

Common failure: user asks for 90s, agent delivers ~200 Chinese characters (~45s spoken).

**Fix**: Check `Round × Duration` in SKILL.md before finalizing. Add a second evidence theme or one follow-up hook sentence—not filler adjectives.

## Over-Claiming Weak Evidence

**Bad**: "I fully owned the memory system" when resume/interview says a teammate owned it.

**Fix**: State boundary clearly; move depth to `可能追问` prep.

## Template Gloss

**Bad**: "我学习能力强、沟通能力好、抗压能力强。"

**Why it fails**: Trait stacks sound safe but give the interviewer nothing to ask about.

**Fix**: Replace each trait with a small behavior: what the user handled, what was difficult, how they checked or followed up, and why it matters for the role.

## Ordinary Experience Over-Packaging

**Bad**: Turning a course project, internship support task, or spreadsheet cleanup into "全面主导", "核心负责人", or "显著提升".

**Fix**: Keep the scope honest: "参与", "协助", "负责其中的", "整理", "核对", "跟进". A small real proof is better than a big claim that collapses under follow-up.

## Outcome Promises

**Bad**: "通过率100%", "保证拿offer", "面试官一定喜欢".

**Fix**: Remove the promise. Say the intro is more specific, lower-risk, easier to follow up on, or less template-like.

## QuickStart Pretending To Be JD-Specific

When quickStart has only a role name:

- Do **not** write company-specific motivation.
- Do **not** say "这个岗位最看重..." as fact.
- Use "基于这个岗位的常见要求，我先假设..." and list what needs confirmation.

## English = Translation

**Bad**: Chinese script translated line by line with long clauses.

**Fix**: Rewrite in short English sentences. Keep section headings in Chinese for Markdown bundles; use `Requirement` as the evidence table column for English JDs.
